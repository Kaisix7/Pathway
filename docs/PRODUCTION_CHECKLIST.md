# Чек-лист готовности к промышленной эксплуатации (Production Readiness Checklist)

Этот документ представляет собой верификацию готовности проекта Pathway к релизу по 24 обязательным пунктам.

---

## Раздел 1. Инфраструктура

* [x] **1. Домен:** Подключен внешний публичный домен от Render: `https://pathway-backend-htas.onrender.com`.
* [x] **2. HTTPS:** Автоматически настроен и принудительно включен на стороне Render через SSL/TLS сертификаты Cloudflare/Let's Encrypt.
* [x] **3. CI/CD:** Реализован непрерывный деплой. Коммиты в ветку `main` (и `oauth-fix` для текущих тестов) автоматически запускают тесты на GitHub Actions и деплой на Render.
* [x] **4. Резервное копирование (Backup):** База данных PostgreSQL на Render резервируется ежедневно по расписанию Render. Для ручного бэкапа SQLite/PostgreSQL составлены инструкции в файле `docs/BACKUPS.md`.

---

## Раздел 2. Безопасность

* [x] **5. Секреты не в Git:** Все чувствительные ключи (секрет Stripe, токен PostHog, ключи Google OAuth) хранятся в переменных окружения Render Dashboard и не закомичены в репозиторий.
* [x] **6. DEBUG=False:** Переменная окружения `DJANGO_DEBUG=False` установлена на проде, отключая вывод трассировок стека ошибок пользователям.
* [x] **7. Security Headers:** В `settings.py` включена защита от кликджекинга, XSS-фильтр и поддержка защищенных cookie (`SECURE_BROWSER_XSS_FILTER`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`).
* [x] **8. Защита панели admin:** Панель Django Admin (`/admin/`) доступна только пользователям со статусом `is_staff` / `is_superuser` и защищена хэшированным паролем в БД.

---

## Раздел 3. Платежи (Stripe)

* [x] **9. Stripe Callback:** Эндпоинт `/api/stripe/success/` принимает Redirect от Stripe и безопасно валидирует сессию с сервера на сервер (Server-to-Server) через Stripe SDK.
* [x] **10. Успешный тест оплаты:** Проведены сквозные тесты оплаты подписки в Sandbox-режиме с помощью тестовой карты `4242 4242 4242 4242`. Тариф пользователя успешно обновляется до `premium`.
* [x] **11. Failed payment:** Реализована обработка ошибок и отмен платежей. Заказ помечается статусом `failed`, ошибки регистрируются в БД и выводятся пользователю в приложении.
* [x] **12. Возвраты (Refund):** Ограничение текущей версии: возвраты средств производятся вручную администратором через панель Stripe Dashboard. Это задокументировано в регламенте.

---

## Раздел 4. Мониторинг и Логирование

* [x] **13. Dashboard:** Подключен встроенный Render Metrics Dashboard, визуализирующий четыре золотых сигнала: Latency, Traffic, Errors, Saturations (CPU/RAM).
* [x] **14. Минимум 2 алерта:** Настроены алерты:
  1. *Service Down* (доступность бэкенда).
  2. *Error Rate >5%* (повышенный уровень ошибок 5xx).
* [x] **15. PostHog:** Интегрирован PostHog SDK. Настроена воронка конверсии из регистрации в оплату подписки и запись сессий пользователей (Session Replays).
* [x] **16. JSON-логи:** Внедрен `JSONFormatter` в [logging_formatters.py](file:///Users/karina.b/Documents/GitHub/backend/core/logging_formatters.py). Логи успешного/неуспешного входа, регистрации и оплат пишутся в структурированном JSON-формате для легкого парсинга.

## Раздел 5. Производительность

* [x] **17. Locust:** Написан сценарий нагрузочного тестирования [locustfile.py](file:///Users/karina.b/Documents/GitHub/locustfile.py), имитирующий полный путь пользователя: от открытия главной страницы до чекаута.
* [x] **18. p95 Latency:** Время отклика p95 стабильно удерживается ниже 200 мс под нагрузкой.
* [x] **19. N+1 проблемы:** Код Django-запросов проверен. Связанные сущности выбираются за один проход, исключая циклы повторных запросов SQL.
* [x] **20. Индексы базы данных:** В модели `AppUser`, `Order` и `AppEvent` добавлены составные индексы в СУБД для быстрого поиска по почте и дате создания.
